01 — The problem

A procurement day, and what it costs

The three things a farmer most needs to know are the three a procurement centre has no way of telling them. Everything below is the gap KisanQ was built to close.

As it is now

  1. Before dawnLeaves home early, because nobody can say when the turn will come.
  2. At the gateHours in a tractor-trolley queue. Position unknown, wait unknown.
  3. At the scaleWeight, moisture and grade are recorded. The farmer sees none of it.
  4. After the sale“Payment in process.” No date, nothing to plan around.

With KisanQ

  1. Books a slotUp to two days ahead, after comparing centres on live wait and remaining capacity.
  2. Watches the queueA live count of farmers still ahead, which falls as the counter works.
  3. Sees the weighingWeight, moisture and grade appear on the phone as the operator records them.
  4. Gets a dateA payment stage and an expected date, not an open-ended wait.

The counter flow conceptual diagram

  1. Check inScan the token QR, or type the number — manual entry is always on screen.
  2. QueueWaiting, processing and completed, in arrival order. Call the next farmer.

  5. Accept or rejectBoth ask for confirmation; a rejection requires a reason.

04 — Stated plainly

What is built, what is simulated, what is not

KisanQ is an independent prototype. Being specific about its edges is more useful than claiming more than it does.

Implemented
Android app, live web portal, a cloud database with real-time listeners and server-side access rules, and the full flow end to end: slot booking, check-in, live queue, weighing, quality check with MSP pricing, payment stages, objections, and notifications in twelve languages.
Simulated
Payments. Stages, amounts and dates are genuine records in the database. No money is transferred, and no bank or payment system is connected.
Demo verification
Aadhaar and OTP are mocked. No UIDAI service is contacted and no Aadhaar number is stored — only an internal reference token. Any twelve digits are accepted in the demo.
Not built
SMS and IVR for farmers without a smartphone. Every notification is already written to a log in the shape a gateway would need, but no gateway is connected.
Unfinished
A government-services interoperability module exists on a separate development branch. It is incomplete, is not part of this release, and is not presented as working.

05 — Try it

Install the Android app

The build is distributed directly as an APK, outside the Play Store. Android will ask you to allow installs from your browser the first time.

Never enter a real Aadhaar number. Identity verification in this build is a demonstration only. Type any twelve digits — for example 1111 1111 1111. Real Aadhaar details must not be entered into KisanQ by anyone, at any time.

  1. Scan or tapAbout 110 MB — use Wi-Fi.
  2. Open the downloaded fileAllow the install when Android prompts.
  3. Sign in with the demo flowAny twelve digits stand in for the Aadhaar number; the one-time code is shown on screen.

06 — About

An independent student project

KisanQ was designed and built by Team CodeCrew as an independent prototype, originally for Smart India Hackathon problem statement SIH26032 on procurement waiting times and status transparency.

Not affiliated with any government body. KisanQ is not endorsed by, commissioned by, or connected to any ministry, department, mandi board or procurement agency, and is not integrated with e‑NAM, any state procurement portal, UIDAI, or any banking system. Centre names, staff accounts and procurement records in the app are demo data.

About the images here. Every phone screen is a real capture from the running Android build, and the sign-in screen is a real capture of the live staff portal. The counter flow, the admin capabilities and the two panels in the live-flow section are labelled diagrams: capturing the operator and admin screens requires signing in, which writes to the project database, and that was deliberately not done. No screen on this site is invented.
